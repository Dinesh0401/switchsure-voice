# Accessibility checklist

- Use WCAG 2.2 AA as the conformance baseline.
- Give every input an accessible name, instructions, and programmatically associated error.
- Keep visible focus and a logical focus order.
- Support record, stop, upload, review, edit, confirm, undo, and export with a keyboard.
- Announce recording start/stop, processing start/completion, and blocking errors through an appropriate live region.
- Do not stream every transcript token to a live region.
- Pair risk colors with text and icons; maintain contrast in every state.
- Provide a typed alternative to voice input.
- Avoid time limits; where unavoidable, allow extension and preserve work.
- Test at 200% zoom, narrow viewport, reduced motion, Windows high contrast, keyboard only, and at least one screen reader/browser combination before release.
- Ensure target sizes, spacing, and error recovery are usable for tremor and low-precision input.
- Never claim WCAG conformance from automated checks alone.
